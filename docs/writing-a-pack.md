# Writing a pack

A pack turns an approved solution model into a runnable app and verifies it. The existing example is `packs/sidecar-django/`.

## Layout

```
packs/<name>/
  pack.yaml        descriptor
  policy.yaml      pack policy (may be an empty mapping)
  <entry>/         importable Python package (the `entry` below)
```

`policy.yaml` must exist (`asb check` reads it); `{}` is valid.

## `pack.yaml`

| Key | Meaning |
|---|---|
| `name` | Pack name; matches the folder and `status.json` |
| `entry` | Importable package inside the pack folder; the loader puts the pack folder on `sys.path` and imports it |
| `field_types` | Subset of: text, number, decimal, money, date, datetime, choice, boolean, attachment, link, external_ref, table |
| `workflow` | `true` if the pack implements workflows |
| `reports` | `true` if the pack implements reports |
| `permissions` | Subset of: create, read, update, update_own_draft, delete, approve, export |

`asb validate` and `asb build` reject a model that uses anything the pack does not declare.

## Entry points

The entry package exports two functions. `root` is the project root (the folder holding `packs/` and `solutions/`); the CLI passes it by keyword.

```python
from asb.model import Solution
from asb.plugins import GenerateResult, VerifyResult, CheckResult


def generate(
    solution: Solution, solution_dir: Path, root: Path | None = None
) -> GenerateResult: ...
def verify(
    solution: Solution, solution_dir: Path, root: Path | None = None, **_
) -> VerifyResult: ...
```

- `GenerateResult(written: list[str], skipped_ai_owned: list[str])`: files written, and AI-owned files that already existed and were kept.
- `CheckResult(name, status, details)`: `status` is `"pass"`, `"fail"` or `"skipped"`. Put the reason in `details` for skips; the first line shows in the report table and the full text under Failures.
- `VerifyResult(checks: list[CheckResult])`. The run passes when no check is `fail`. Never turn a check you could not run into a pass.

`solution_dir` is `solutions/<name>/`; write the app under `solution_dir / "app"`.

## Generation rules

1. **Deterministic**: the same model gives the same files.
2. **Header**: every generated file starts with `# GENERATED by asb — do not edit; regenerate from solution.yaml` (`//` for TypeScript).
3. **AI-owned files**: write a stub once and never overwrite an existing one; return it in `skipped_ai_owned`. Stubs must not carry the header. Decide a naming rule so leftovers can be found, and **fail before writing anything** when a stub no longer matches the model (orphan).
4. **Manifest and anchor**: write `app/.asb-manifest.json`, a JSON object of app-relative path to SHA-256 of every generated file, then call `asb.checks.write_anchor(root, solution_dir.name, app_dir)` to record its hash in `<root>/.asb/manifests/<solution>.sha256`. `asb check` compares files against the manifest and the manifest against the anchor (`HEADER_TAMPERED`).
5. **Connector**: read the connector name from `status.json` (never hard-code it), resolve it with `asb.plugins.read_connector_info`, and vendor `asb/connector.py` plus the connector package into the app so the app has the same imports as the builder.
6. **Traceability to tests**: generate matrix tests from the model (permissions, workflow) and a skeleton per acceptance test.

## Verification

`verify` should run real evidence and return one `CheckResult` per area. `sidecar-django` returns: `acceptance_mapping`, `tests`, `permission_matrix`, `workflow_matrix`, `reports`, `static`, `frontend_build`, `ui_smoke`. Run generated apps in a subprocess so their settings never leak into the builder. Report missing tools (`npm`, a browser) as `skipped` with a reason.

## `policy.yaml`

Merged onto `core/policy/policy.yaml` by `asb check`: lists are unioned, other core values win, so a pack can only tighten. (The PreToolUse hook's `deny_commands` come from the core policy only.)

| Key | Meaning |
|---|---|
| `skip_paths` | Globs (relative to `app/`) of generated-manifest files exempt from pattern checks, such as vendored code and migrations |
| `ignore_paths` | Globs never walked (dependencies, VCS data) |
| `build_output` | Globs of build output that is not scanned |
| `no_permission` | `base_classes` and `attribute`: view base classes that must define a permission attribute (`NO_PERMISSION`) |

## Testing a pack

Build a small fixture solution into a temp folder, call `generate` twice (the second run must keep AI-owned files and rewrite generated ones identically), edit a generated file and confirm `asb check` reports `HEADER_TAMPERED`, then run `verify`. See `tests/sidecar/`.
