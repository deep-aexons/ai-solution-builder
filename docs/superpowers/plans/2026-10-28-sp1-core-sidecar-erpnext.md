# Sub-project 1 — Core + Sidecar Pack + ERPNext Connector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude plugin + `asb` CLI that takes a plain-language request through requirements, design, build and verification, generating a Django/DRF/React sidecar app that reads ERPNext through a connector — proven by the Gate Pass pilot.

**Architecture:** Platform-neutral core (`core/tool/asb`: model, validator, stage gates, pack/connector loading, checks, hooks) drives packs and connectors through small Python interfaces. The `sidecar-django` pack generates generator-owned files from Jinja2 templates and leaves AI-owned files (rules, report logic, test bodies) alone. The ERPNext connector is a standalone package that is vendored into each generated app.

**Tech Stack:** Python 3.12 (uv), pydantic 2, PyYAML, Jinja2, Typer, httpx, pytest; generated apps: Django 5.2 LTS, djangorestframework 3.15+, React 18 + TypeScript + Vite 5, PostgreSQL 16 (Docker Compose) with SQLite fallback for local tests.

**Spec:** `docs/superpowers/specs/2026-10-28-ai-solution-builder-design.md`

## Global Constraints

- Core (`core/`) must not import or name any ERP, framework or pack. Grep check: `rg -i "erpnext|frappe|django" core/` returns nothing outside comments in `core/policy/policy.yaml`.
- Python ≥ 3.11 (develop on 3.12). Single root `pyproject.toml`; packs and connectors are importable packages inside their own folders (`packs/sidecar-django/asb_sidecar`, `connectors/erpnext/asb_erpnext`), loaded by path via their YAML descriptors.
- Field types exactly: `text, number, decimal, money, date, datetime, choice, boolean, attachment, link, external_ref, table`.
- Permissions exactly: `create, read, update, update_own_draft, delete, approve, export`.
- Names: snake_case `^[a-z][a-z0-9_]*$`; rule ids `^R\d+$`; acceptance test ids `^AT-\d{2,}$`.
- Generated files start with the line `# GENERATED by asb — do not edit; regenerate from solution.yaml` (`//` for TS). AI-owned files never carry it and are never overwritten.
- Connectors: no delete/submit/cancel operations exist. `create_draft` only for operations listed as `write:<operation>` in the approved model.
- Credentials only from environment variables (`ASB_ERP_URL`, `ASB_ERP_API_KEY`, `ASB_ERP_API_SECRET`).
- Build/verify fix loops: max 3 rounds per solution (tracked in `status.json` as `verify_rounds`).
- Execution environment note: the dev VM has no Docker and cannot reach `erpnext.localhost`. Tests use SQLite and a mock ERP; Postgres/Compose and live-ERP tests are marked `@pytest.mark.compose` / `@pytest.mark.live_erp` and skipped unless `ASB_COMPOSE=1` / `ASB_ERP_URL` is set. UI smoke (Playwright) is reported as `skipped` with a reason when no browser is available.

## Review Focus

1. A `solution.yaml` with a typo'd key or wrong type → `asb validate` prints the YAML path and message, never a traceback (Task 2 test `test_unknown_key_reports_path`).
2. Model edited after design approval → `asb build` refuses with "approved hash differs" (Task 4 test `test_build_refused_after_model_change`).
3. Regenerating after the AI wrote rule code → AI files byte-identical; a rule removed from the model while its file still exists → generation fails naming the orphan file (Task 9 tests).
4. ERP unreachable or 401 while saving a gate pass → API returns 400/503 with a readable message, not 500 (Task 14 test `test_r1_erp_unavailable_returns_503`).
5. Reference document deleted/cancelled in the ERP → R1 refuses with "not found or not submitted" (Task 14 test `test_r1_cancelled_reference_refused`).
